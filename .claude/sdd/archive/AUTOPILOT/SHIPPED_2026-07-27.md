## Summary

Autopilot V0 lets a user state one intent and receive either an open PR or an actionable gap report — never a mid-run question. `/auto "<intent>"` executes the full SDD workflow (self-answering Brainstorm → Define → Design → Build → Ship → PR) with the existing quality gates deciding proceed/retry/abort under bounded budgets; a policy-free headless runner (`scripts/autopilot.sh`) provides the same flow for CI/cron. The gate policy exists in exactly one file (the `sdd-autopilot` skill), consumed by both entrypoints, and every run writes `AUTOPILOT_RUN_{FEATURE}.md` — a gate ledger that doubles as resume state. This brings lights-out autonomy into AgentSpec while adding zero new sensors and modifying zero existing phase contracts.

## Lessons Learned

### Process

- **Parity by construction beats parity by testing.** The headless runner invokes the exact same `/auto` command instead of re-driving phases in bash (rejecting the brainstorm's literal Approach C). This one Design decision made "0 duplicated policy rules" trivially true and deleted an entire drift-test dimension — the most leveraged 20 minutes of the feature.
- **Delegate with "report bugs, don't fix" + orchestrator triage.** The test-generator surfaced 4 runner findings; the orchestrator fixed the 2 cheap/safe ones and accepted 2 with rationale, all recorded in the BUILD_REPORT. Separating finding from fixing kept ownership clear and made the unattended build auditable.
- **Honest test-strategy splits survive scrutiny.** Declaring upfront which acceptance tests are automatable (runner mechanics) versus model-dependent (gate behavior → documented E2E procedure with induced-failure recipes) avoided fake automation and left a runnable validation path for release day.

### Technical

- **Design-doc code skeletons are behavior contracts, not implementations.** The DESIGN's 12-line runner skeleton contained a real bug — `ls | head -1` dies under `set -euo pipefail` when no report exists, making "no report" indistinguishable from "Aborted". The shell specialist caught it only because the delegation demanded testing the no-report path explicitly.
- **Tier selection is the contract-clean way to bound a probabilistic judge.** Running spec-judge at the standard tier (WARN-capped by construction) makes it impossible for the judge to block a run — without reinterpreting any verdict, which ADR-003 forbids. Choosing where FAIL is unreachable beats promising to ignore FAIL.
- **One document as both report and state eliminates drift by construction.** The RUN REPORT's gate ledger is the resume state; there is no second state file to fall out of sync. Rule that made it work: approval lives in the ledger row, never in artifact existence.
- **A stubbed CLI on PATH makes model-invoking scripts unit-testable at zero API cost.** Fourteen hermetic tests (fake `claude` writing parameterized reports, from-scratch PATH/HOME) cover every deterministic runner branch in 4 seconds.

### Communication

- **Recording decision reversals in the BRAINSTORM prevented re-litigation.** The user reversed three earlier answers at the YAGNI review (all-on-by-default); the document kept the revision trail explicit, so Define and Design consumed the final decision without ambiguity about which answer was current.
- **Naming assumptions as load-bearing (A-002/A-003) focused the Design.** Two of six assumptions were flagged as the ones that could invalidate the architecture; both got resolved as the first two ADRs instead of being discovered mid-build.

### Tools & Libraries

- **spec-linter/spec-judge exit-code contracts (0/1/2[/3/4]) were reused unmodified** — autopilot consumed five existing sensors and built zero. The "visible skip, never assumed PASS" convention generalized cleanly from one consumer (/define) to an orchestrator.
- **shellcheck at `-S warning` + explicit script enumeration** caught nothing in the final runner but forced the discovery that by-name lint lists silently exclude new scripts — now wired for `autopilot.sh` in both Makefile and CI.
